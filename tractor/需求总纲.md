# 需求总纲 —— 《拖拉机》(升级/双升) 手机版

> **原始需求（用户原话）：** 把文件夹内的 tractor.exe 变成适配 vivo x500 pro max 手机的 apk 软件，我想让妈妈能玩到。

## 一、来源确认

`tractor.exe` 是 1997 年 PowerInfo Co. Ltd. 出品的《拖拉机 Ver 1.1》Windows 纸牌游戏（MFC 程序），即经典 4 人 2 副牌升级（拖拉机/双升）。从二进制提取到的关键信息：

- 名称：Tractor Ver 1.1；开发商 PowerInfo Co. Ltd.；版权 1997.10
- 花色：CLUB / DIAMOND / HEART / SPADE + 大王/小王
- 计分：**5、10、K**（5=5 分，10=10 分，K=10 分）
- 变体选项：`5,10,K` / `J,A` 计分、`Anti Joker`（反王）、`Zi Fan`（自反）、`Is Qiang`（抢）、`NOTRUMP`（无主）、`Start from 2`（从 2 打起）
- 操作：`PASS`（过）、`TAKE`（拿分）、`TWO`（出对）
- 难度：Easy / Hard / High；速度、牌面（Arts / Sport / Normal）、改名、音乐/音效
- 联机：Network games / 多人对战 / 玩家列表（原版有 WSOCK32 联网）
- 存档：`Game.dat` / `Game.sav`

## 二、交付目标

1. **触屏版《拖拉机》游戏**，规则忠实于原版（标准 2 副牌 80 分升级）。
2. 单人 vs 3 个电脑 AI（原版也有单机模式）。
3. 大字体、大牌面、好点击，适合中老年玩家。
4. 界面适配手机**横屏**比例；发牌速度可调；出牌时可查看上一圈结果；手牌按花色分组（主在前，再黑桃、红桃、梅花、方块）。
5. 最终打包成 **Android APK**，装到 vivo X500 Pro Max 上离线可玩。

## 三、技术路线

- 游戏本体：HTML + CSS + 原生 JavaScript（静态网页，无需构建步骤，便于本地测试与后续打包）。
- 打包：用 Capacitor / Cordova 把静态网页包成原生 Android WebView APK（需安装 JDK + Android SDK）。
- 分阶段：
  1. 阶段一：可玩网页版（本仓库 `tractor/` 目录）。
  2. 阶段二：APK 打包。

## 四、核心规则（实现基线）

- 2 副牌共 108 张，4 人 2 对 2（对家为搭档），每人 25 张，底牌 8 张。
- 级牌 = 发牌方（上局庄家队伍）的等级点数（从 2 开始）；主牌 = 大小王 + 全部 4 张级牌 + 主花色其余牌。
- 发牌亮主：**逐张发牌**，过程中随时可亮主/改主。出主顺序严格三档，**同一档不能互相反**：
  1. **亮主** = 单张级牌
  2. **反主** = 同一花色的**两张**级牌（`kind:'pair'`）
  3. **反无主** = **两张同样的王牌**（大王×2 或 小王×2，大小各一张不算）；两张大王可反两张小王。
  谁**首亮**谁坐庄（被反主不换庄），拿底牌。**仅第一局如此**：之后坐庄由轮转决定，亮牌只定主牌花色（见下「坐庄在胜利者之间轮转」）。
- **加保**：自己亮出单张之后，又抓到**同一花色的第二张级牌**，可以当场加保
  （单张 → 两张，`own:true`）。加保之后这一门就锁死了——别人**再也不能用别的花色的
  一对级牌来反**，只剩「两张同样的王」还能翻无主。加保也**不换庄**，还是首亮者坐庄。
  判据是 `bidIsOwn(bid)`：**必须是同一门**才叫加保。自己原先亮黑桃、现在改亮梅花，
  那是**换门**不是加码，战报里写「反主」，不写「加保」。
- **发牌会停下来等人**：只要玩家手上**新**出现了一个压得过桌上主牌的叫法
  （第一次能亮主 / 抓到第二张能加保 / 凑齐双王能反无主），发牌就停下。
  同一个叫法只停一次，免得每张牌都停。
  不停的话 AI 会在下一张牌就把主定死，玩家连加保的机会都没有。
- **亮牌阶段摆一排位置固定的叫牌按钮**（照 1997 原版的样子）：**四个花色 + 小王 + 大王，
  永远六个，位置一辈子不动**，不用玩家自己去手牌里点牌，也不用在一排会变来变去的文字里找。
  - **哪里亮了点哪里**：能亮的那个金黄发亮，点不动的压暗（仍然占着位置，不会左右乱窜）。
  - **「自保时再复亮一次」**：手里攥到同一门的第二张级牌，那个花色按钮**再次亮起来**，
    角上挂个「×2」角标——再点一次就是**加保**（单张 → 两张），一眼看得出这次点下去是加码不是单纯亮主。
  - **只有「亮/不亮」一个信号**，不另标「当前主是哪门」：牌堆正中已经把主牌连牌带人摆着了，
    再给灰按钮套个金圈，会让人以为它也能点。
  - 按钮的悬浮说明（`title`）才写长句子（「亮主·黑桃」「加保·两张梅花」「大王：得攒够两张一样的」）。
  - 一门都亮不了时六个按钮全灰，提示文字在左上角说明原因。
- **主牌摆在牌桌正中**：从有人亮主起，那张（或两张）主牌就带金框摆在牌堆区正中
  写明是谁亮的主，**一直到开始扣底**才收起来（那会儿牌桌要压矮给手牌腾地方）。
- 出牌：单张 / 对子 / 拖拉机（连对）/ **甩牌**，跟牌须同门同结构，有对必对，无此门可贴牌或将吃。
- **甩牌**：同门多组（如 ♠A + ♠K♠K）可一次甩出。判定「会不会失败」**只比同门**，
  比较池 = **其他三家的手牌 + 自己手里这一门还没出的牌**。
  例：红桃剩 `A Q Q 7 6 5 5 4 2 2`，A 手里 `A Q Q 7 4 2 2`，别人有 `6` 和 `5 5`
  → A 可以一把甩 **`A Q Q 7`**（`4` 被 `6` 压、`2 2` 被 `5 5` 压，甩不出去）。
  失败了按「最小规则」改出**被压住的那组里最小的一组**。
  主门是特例：把**大小王**和**当前级牌**一起算作同门来比较。
  **将吃不算「甩牌失败」，但甩牌本身可以被将吃**——而且必须用**同样的牌型**整手主牌来毙
  （甩 ♠A ♠Q♠Q 是三张「1 单 + 1 对」，就得拿主牌摆成「1 单 + 1 对」才毙得掉；
  摆成三张单张就不行）。结算见 `resolveTrick` 的甩牌分支 + `shapeVariants()`。
  **拖拉机不吃「被压」这一套**：相邻的 `AABB` 可以一直甩，不看别人有没有更大的 `CC` 或 `CCDD`。
  **AI 甩牌前用完美信息作弊，永远不甩错**（`Game.aiThrow` + `throwFailReason` / `safeThrowSubset`）。
  **提示只在甩出去之后给**：事前绝不告诉玩家能不能甩、该甩哪几张，否则失败惩罚就没意义了
  （失败时弹红色横幅：被谁压了、改出了什么、这手本可以甩什么。红条贴在**牌桌右上角**，
  封顶 260px 宽、**4.2 秒**自己消失——它是浮在牌桌上面的，挂久了会压到右座和下家的牌）。
  开新局时红条和招牌**一律清掉**，不许上一圈的遗留飘进下一局的发牌阶段。
  跟甩牌**张数、门数、牌型三样都得对得上**（见下条）。
- **跟牌必须有对必对、有拖拉机必跟，甩牌也不例外**（玩家原话：本轮第一个出牌的玩家出了特殊牌型，
  其他人手里有该花色的同牌型是必须出的。比如第一个玩家出了 `a b c c`，
  那么第二个玩家手里的 `dd` 再不想出，他也得出）。
  - 判法：把跟牌的人**这一门最多能摆出的结构**算出来（`bestShapePick`：先凑拖拉机、再凑对子），
    跟他实际出的牌比；不一样就判无效。手里藏着对子不拿出来，直接拦住。
  - 甩牌领出也走同一条路（以前这里图省事，只卡张数和门数，是错的）。
  - 有个坑：对子和拖拉机都是偶数张，凑不够一整组时零头只能按单张算——
    4 张的拖拉机只让出 3 张时，结构是「一对 + 一张」，不存在「三张」这种组。
  - **判无效时当场把原因贴出来**（角上红条「这么出不行：有对子必须出对子」）：
    不吭声的话，点了「出牌」没反应，只会以为游戏卡住了。
  - **校验和 AI 共用同一个函数**，两边各算各的话，会出现「AI 出的牌被判无效」这种自己跟自己打架的事。
- **招牌只给「有故事」的那一手**（`handFlourish(plays, i)`），**按出牌人分开判，不再四家一起喊**：
  - **领出的那一家**：出拖拉机 → 「拖拉机！」（超过 6 张写「大拖拉机 N 张！」）；
    甩牌 → 「甩 N 张！」；单张 / 对子不喊。
  - **跟牌的**：先拿引擎现算 `resolveTrick(plays.slice(0, i + 1))`，
    **算出来的赢家等于自己**（=真把场上的牌压过去了）才给招牌——
    否则被迫跟一手牌的人凭什么喊「甩牌」。压过去了再看性质：
    - **出了大王** → 「金墩布！」；**出了小王** → 「银墩布！」
      （大小王画的就是家里那只猫，用王压住是最值得喊一声的）
    - **主牌毙副牌** → **「大过你！」**（只有这一种情况喊）
    - **副牌同门更大 → 不喊**（红桃10 压红桃9 这种）。跟牌本来就该尽量管住，
      两家副牌你来我往是家常便饭，喊一句「大过你！」反倒像在咋呼
      ——用户原话：「打个副牌红桃9和红桃10，俩人有啥可横的」。
    - **主牌压主牌 → 不喊**（你出 ♥5、人家出 ♥K 这种）。一巡能弹三下，满屏都是，
      而且主牌谁大谁赢本来就是常事，喊了反倒咋咋呼呼。
  - 注：甩牌领出**只能被整手同样牌型的主牌毙掉**（同门再大也压不过），
    所以跟甩牌的人拿到的是「大过你！」——正是毙牌那一种，对得上。
  - 亮招牌的那一手会镶一圈**金边**，金边**一直挂到这一圈结算**
    （每次有人出牌整圈会重画，不能因为重画就掉了）。招牌动画一手只弹一次，重画不重播。
- 计分：5/10/K 为分牌，共 200 分；闲家 ≥80 上台，<40 小光、=0 大光。
- **抠底**：最后一圈赢家若为闲家，底牌分按 **(最后一圈出牌张数 + 1)** 倍计入闲家得分。
  例：最后一圈「双 K」抠底（2 张），圈内共 25 分、底牌 10 分 → `25 + 10 × 3 = 55`。
- 升级：**从 2 打到 A，再到「王」**；在「王」这一级守庄成功 = 绕完一整圈，**等级回到 2 接着打**。
  **游戏无限循环，没有终局**——打到不想玩为止；每次绕完一圈会弹一个**表扬横幅**（`#banner`）。
  战报栏右上角有「重开」按钮，随时可以重新开局。
- **首轮无人亮主**：默认**玩家坐庄**并**打无主**（主牌 = 4 张王 + 8 张级牌）。
- **坐庄在胜利者之间轮转（从第二局起）**：庄家队守住了 → 交给**搭档**（坐庄位 +2）；庄家队被打下来 →
  交给赢的那队的**下一家**（+1）。例：东家坐庄，赢了换西家（搭档），输了换北家。
  （座位按出牌顺序编号 0=东、1=北、2=西、3=南，对家是搭档，隔 2 个座位。
  **第一局由亮牌定庄；之后亮牌只决定主牌花色，不再决定谁坐庄。**）
- 每局结束：**对家会鼓励几句，对手会嘲讽（他们赢）或夸赞（他们输）**，用气泡显示。

## 六、AI 策略（`game.js`）

- **队友意识**：对家（同队）正赢着这一圈时不抢；自己是最后一家时把分牌喂给队友。
- **记牌**：`playedCards` 记录本局所有已出牌，`unseenStronger()` 推算某张牌是否还被人压得住。
- **叫牌不无脑**：`aiBidNow` 从强到弱挨个掂量（`aiWantsBid`），划算才叫，不再「见着双王就翻无主」。
  - 反无主（`worthNoTrump`）：先看**亮出来的那一门对我方是不是太薄**——
    自己和队友在这门上加起来不到 8 张、而自己手上攒着 4 张以上的王/级牌（打无主这些全是主），才翻；
    自己坐庄而那门自己只剩两三张，也翻。桌上还没定主就不翻（两张王留着当主牌更值）。
  - 反花色（`worthReverse`）：换过去的那门要明显比我方原来那门厚（多出 2 张以上）才值得翻。
  - 实测：400 局里 AI 反无主从「只要手上有双王、桌上有主就必翻」降到约 19 次。
- **领出**：先出副牌的靠谱大牌——甩牌 → 稳大的对子/拖拉机 → 单 A（都只看副牌门）；
  副牌没大牌了才打主（对王、对级牌、对主 A，再庄家拉主调主）；最后从短门出小牌造空门、把牌权让给对家。
- **跟牌**：能管住就管住；自己是最后一家且稳赢时，改出分最多的组合把分甩出去。
- **垫牌/将吃**：优先垫非主、非分、短门；只在圈里有分或对方出对子/拖拉机时才将吃。
- **扣底**：优先扣副牌、非分、低、短门的牌（造空门），保留主牌与分牌。
